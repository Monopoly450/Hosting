# Панель управления хостингом виртуальных машин и внешним мониторингом (KubeVirt + K3s + SSH)

Эта платформа представляет собой полноценный центр управления виртуализацией и мониторингом серверов. 

Она позволяет:
1. **Оркестрировать локальные ВМ** (через Kubernetes, KubeVirt и Multus CNI), предоставляя виртуалкам реальные IP вашей домашней сети.
2. **Управлять кастомными образами** дисков и ISO, а также делать резервные копии и расширять диски ВМ.
3. **Управлять Docker контейнерами** на хост-системе.
4. **Мониторить внешние Linux-серверы** по IP и паролю через SSH (сбор системных метрик, процессов, Docker-контейнеров и служб Systemd) без установки каких-либо агентов.

---

## Возможности панели

* 🌐 **Внешний мониторинг серверов:** Подключайте любые Linux-машины по IP и SSH. Отслеживайте CPU, RAM, накопители, запущенные службы Systemd, топ процессов по нагрузке и контейнеры Docker.
* 💾 **Резервное копирование ВМ:** Создание резервных копий дисков "на лету" с помощью нативного клонирования PVC в Kubernetes и быстрое восстановление с автоматической остановкой ВМ.
* ⚙️ **Изменение ресурсов:** Динамическое изменение ядер CPU, объема оперативной памяти и физического диска ВМ (с защитой от сжатия диска).
* 🔑 **Root-доступ:** Автоматическая генерация случайного пароля root при создании ВМ с выводом данных в личном кабинете.
* 💿 **Свои образы:** Загрузка файлов `.qcow2`/`.img`/`.iso` через веб-интерфейс с отображением прогресса загрузки.
* 🖥️ **noVNC Экран:** Управление дисплеем виртуалки (включая установку Windows) прямо из окна браузера.
* 🐳 **Docker Админка:** Старт, стоп и перезапуск контейнеров на хост-сервере.

## Требования к хосту (VMware)

Для работы локального гипервизора KubeVirt внутри вашей виртуальной машины Ubuntu в VMware:
1. Выключите вашу виртуалку Ubuntu в VMware.
2. Перейдите в **Настройки (Virtual Machine Settings) -> Процессоры (Processors)**.
3. Активируйте чекбокс: **"Virtualize Intel VT-x/EPT or AMD-V/RVI"** (Виртуализировать Intel VT-x/EPT или AMD-V/RVI).
4. Запустите виртуалку обратно.

---

## Шаг 1: Авто-настройка окружения Kubernetes + KubeVirt

Перенесите скрипт `scripts/bootstrap-host.sh` на ваш хост Ubuntu, сделайте его исполняемым и запустите от `root`:
```bash
chmod +x bootstrap-host.sh
sudo ./bootstrap-host.sh
```
Скрипт установит K3s, настроит Multus CNI (сетевой мост в домашнюю сеть), развернет KubeVirt и CDI, а также скачает утилиту управления `virtctl`.

---

## Шаг 2: Запуск панели управления хостингом

Панель управления разворачивается через Docker Compose в режиме `host-networking` для прямого доступа к API Kubernetes.

1. Установите Docker Compose на вашу Ubuntu:
   ```bash
   sudo apt-get update && sudo apt-get install -y docker-compose
   ```
2. Запустите сборку и старт панели:
   ```bash
   sudo docker-compose up -d --build
   ```
3. Контейнеры запустятся на хост-сети:
   * **Веб-интерфейс панели** будет доступен по адресу: `http://IP_ВАШЕГО_СЕРВЕРА:8080`
   * **API бэкенд** работает на порту: `http://IP_ВАШЕГО_СЕРВЕРА:8000`

## Руководство по работе с вкладками дашборда

### 1. Дашборд ВМ (Создание и управление локальными виртуалками)
* **Создание ВМ:** Выберите тип ОС (Ubuntu Cloud, Windows ISO или Свой образ), введите имя, укажите лимиты ресурсов и нажмите кнопку создания.
* **Доступ:** Логин по умолчанию для Linux-систем — `root`. Случайный пароль сгенерируется автоматически. Скопируйте его из реквизитов доступа на карточке ВМ.
* **Экран (noVNC):** Нажмите кнопку «Экран» для вызова веб-консоли. При установке Windows Server выберите дисковод `CD Drive (E:) VirtIO-Drivers` -> папку `amd64` -> версию ОС (например, `2k22` для Server 2022) для установки драйверов HDD.
* **Резервное копирование:** Нажмите на иконку дискеты на карточке ВМ. Откроется встроенная панель бэкапов. Нажмите «Создать копию». Восстановление диска автоматически остановит ВМ, заменит PVC диска на клон бэкапа и подготовит ВМ к запуску.
* **Изменение ресурсов:** Иконка шестеренки открывает ползунки CPU/RAM и диска. Увеличивать диск можно только в сторону расширения.

### 2. Образы дисков (Хранение собственных ОС)
* Вы можете перетащить или выбрать файл `.qcow2`, `.img`, `.iso` или `.raw` для загрузки в локальное хранилище сервера (`./data/images`).
* Панель отобразит прогресс-бар в процентах. После загрузки образ появится в выпадающем списке создания ВМ в категории «Свой образ».

### 3. Внешние серверы (Агентлесс мониторинг сторонних машин)
* Нажмите **"Подключить сервер"**, введите понятное имя, IP-адрес, SSH-порт, логин и пароль.
* Панель проверит SSH-соединение. В случае успеха сервер появится в списке со статусом «В сети».
* Кликните на карточку сервера, чтобы открыть живой дашборд. На нем отобразится:
  * Загрузка CPU, RAM, диска, а также Uptime и Ядро.
  * Таблица топ-10 активных процессов по использованию CPU (PID, User, CPU%, Mem%, Command).
  * Службы Systemd (список активных системных сервисов).
  * Контейнеры Docker (список контейнеров с их статусом, если Docker установлен на удаленном сервере).

### 4. Docker Админка (Управление контейнерами хоста)
* Во вкладке отображается статус всех контейнеров, запущенных на вашем физическом сервере (включая саму панель хостинга).
* Доступны быстрые кнопки: Запустить (Play), Остановить (Square) и Перезапустить (Rotate).

## Устранение неполадок

* **Проблема с KVM:** Если команда `ls -l /dev/kvm` пуста, значит вложенная виртуализация в VMware отключена. KubeVirt запустится в режиме медленной программной эмуляции.
* **Доступ к K3s:** Если бэкенд пишет ошибки о доступе к K8s, проверьте, что файл `/etc/rancher/k3s/k3s.yaml` доступен для чтения пользователем docker (docker-compose монтирует его автоматически с правами `ro`).
* **Логи бэкенда:** Посмотреть логи работы API и SSH-клиента:
  ```bash
  sudo docker logs hosting-backend
  ```
