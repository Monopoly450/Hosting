# Панель управления хостингом виртуальных машин (KubeVirt + K3s)

Эта платформа позволяет создавать и управлять виртуальными машинами (Ubuntu Server, Windows Server) прямо из веб-интерфейса, используя технологии **Kubernetes (K3s)**, **KubeVirt** и **Multus CNI**.

Благодаря сетевому мосту (Bridge) созданные виртуалки будут получать IP-адреса напрямую от вашего домашнего роутера по DHCP и будут доступны в локальной сети.

---

## Шаг 1: Подготовка процессора в VMware (Хост)

Для работы аппаратного ускорения KVM внутри вашей виртуальной машины Ubuntu в VMware:
1. Выключите вашу виртуалку Ubuntu в VMware.
2. Перейдите в **Настройки (Virtual Machine Settings) -> Процессоры (Processors)**.
3. Обязательно активируйте чекбокс: **"Virtualize Intel VT-x/EPT or AMD-V/RVI"** (Виртуализировать Intel VT-x/EPT или AMD-V/RVI).
4. Запустите виртуалку Ubuntu обратно.

---

## Шаг 2: Установка K3s, KubeVirt и Multus CNI на хосте

Мы подготовили скрипт авто-установки. Скопируйте и запустите его на вашей Ubuntu:

1. Перенесите скрипт `scripts/bootstrap-host.sh` на виртуалку Ubuntu.
2. Сделайте его исполняемым и запустите от имени `root`:
   ```bash
   chmod +x bootstrap-host.sh
   sudo ./bootstrap-host.sh
   ```
3. Скрипт установит:
   * **K3s** (легковесный Kubernetes)
   * **Multus CNI** и сетевой мост (macvlan)
   * **KubeVirt** (гипервизор для запуска VM в K8s)
   * **CDI** (загрузчик дисков и ISO)
   * Утилиту **virtctl**

После завершения проверьте статус компонентов:
```bash
kubectl get pods -A
```
Все поды в пространствах имен `kubevirt`, `cdi`, `kube-system` должны перейти в статус `Running`.

---

## Шаг 3: Запуск панели управления хостингом

Панель управления состоит из бэкенда (FastAPI) и фронтенда (React). Они упакованы в Docker Compose и запускаются одной командой.

1. Установите Docker Compose на вашу Ubuntu (если еще не установлен):
   ```bash
   sudo apt-get update
   sudo apt-get install -y docker-compose
   ```
2. Перейдите в корневую директорию проекта (где находится `docker-compose.yml`) и соберите/запустите контейнеры:
   ```bash
   sudo docker-compose up -d --build
   ```
3. Контейнеры запустятся в сетевом режиме `host`:
   * **Фронтенд** будет доступен по адресу: `http://IP_ВАШЕГО_СЕРВЕРА:8080`
   * **Бэкенд** работает на порту: `http://IP_ВАШЕГО_СЕРВЕРА:8000`

---

## Шаг 4: Использование панели управления

Откройте в браузере `http://<IP_вашей_Ubuntu_в_сети>:8080`.

### Создание Ubuntu Server (LTS 24.04):
1. Введите имя виртуалки (например, `ubuntu-test`).
2. Выберите параметры: CPU (например, 2 ядра), RAM (например, 4 ГБ), Диск (например, 30 ГБ).
3. Введите пароль для входа (по умолчанию: `ubuntu`).
4. Нажмите **"Создать виртуальную машину"**.
5. Панель отправит запрос в Kubernetes. CDI начнет скачивание официального образа диска. Статус виртуалки будет `Importing` (это займет 1-3 минуты в зависимости от интернета).
6. Когда виртуалка перейдет в статус `Running` (Активна), она получит внутренний IP и IP из вашей домашней сети (через Bridge) и станет доступна по SSH:
   ```bash
   ssh ubuntu@<BRIDGE_IP_ИЗ_ПАНЕЛИ>
   # Введите указанный вами пароль
   ```

### Создание Windows Server 2022:
1. Выберите шаблон **Windows Server**.
2. Укажите имя (например, `win-server-01`) и выделите ресурсы (рекомендуется от 4 ГБ RAM и 60 ГБ диска).
3. Нажмите **"Создать виртуальную машину"**.
4. CDI скачает ISO образ дистрибутива Windows Server. После этого виртуалка автоматически запустится.
5. Нажмите кнопку **"Экран"** на карточке виртуалки. Откроется VNC-консоль прямо в вашем браузере!
6. В консоли вы увидите стандартный установщик Windows Server. Установите систему.
   > **Важно:** При выборе диска для установки установщик Windows не увидит жесткий диск по умолчанию, так как мы используем быстрый VirtIO драйвер.
   > Нажмите **"Load Driver"** (Загрузить драйвер) -> **Browse** -> Выберите дисковод **CD Drive (E:) VirtIO-Drivers** -> выберите папку `amd64` для вашей версии ОС (например, `2k22` для Server 2022) -> Диск определится, продолжите установку.

## Устранение неполадок

* **Проблема с KVM:** Если виртуалки запускаются очень медленно или не стартуют, выполните `ls -l /dev/kvm`. Если устройства нет, значит вложенная виртуализация в VMware выключена. Скрипт настроит KubeVirt в режиме эмуляции, но производительность будет низкой.
* **Логи бэкенда:** Если панель не видит виртуалки, посмотрите логи контейнера бэкенда:
  ```bash
  sudo docker logs hosting-backend
  ```
* **Доступ к K3s:** Убедитесь, что файл `/etc/rancher/k3s/k3s.yaml` доступен для чтения (Docker Compose монтирует его автоматически).
