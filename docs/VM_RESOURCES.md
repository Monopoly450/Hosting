# Ресурсы ВМ и дополнительное место

```bash
cd /root/Hosting
git pull
docker compose up -d --build backend worker frontend
```

После обновления перезагрузите страницу панели. Выберите CPU/RAM и нажмите
«Сохранить настройки ресурсов»; само движение ползунка ничего не сохраняет.
Периодический опрос статуса не сбрасывает несохранённые изменения.
CPU/RAM сохраняются в БД и отправляются в Kubernetes валидным Merge Patch.
После повторного открытия страницы используются сохранённые значения.

Для изменения CPU/RAM у уже запущенной ВМ нажмите Stop, дождитесь остановки
и нажмите Start. Перезагрузка внутри гостевой ОС не пересоздаёт VMI и не
заменяет его конфигурацию. Такая остановка вызывает простой приложения.

## Дополнительное место

Начальный размер системного диска выбирается при создании ВМ. В обеих формах
редактирования он показывается только для просмотра: сохранение CPU/RAM
не запрашивает увеличение системного диска.

Чтобы добавить место:

1. Откройте раздел «Сетевые диски».
2. Создайте диск нужного размера.
3. Подключите его к выбранной ВМ.
4. При необходимости настройте разделы, файловую систему и монтирование
   нового диска внутри гостевой ОС. Не форматируйте существующие диски с данными.

Сетевой диск — отдельный дополнительный диск, а не увеличение системного.
Одинаковая подсказка показывается в настройках, окне изменения ресурсов
и форме создания ВМ. После S3-отката показывается сохранённый логический
размер системного диска, а не размер PVC с файловым overhead CDI.
Существующий API расширения диска сохранён для совместимости, но в панели
больше нет соответствующего ползунка.

## Карточка сетевых дисков

Карточка на главном экране называется «Сетевые диски (LVM)». Строка
«Выделено сетевым дискам» учитывает только зарегистрированные сетевые
диски с реальными PVC на LVM. Диски ВМ, архивы и базы данных в эту строку
не включаются. Общая ёмкость, занятое и доступное место относятся к самому
пулу; проверки вместимости не ослабляются.

При `local-path` уже созданный сетевой диск не занимает LVM-пул и не
увеличивает его счётчик. Существующие данные автоматически не переносятся.

Новые сетевые диски используют отдельную настройку
`NETWORK_STORAGE_CLASS=openebs-lvm` (значение по умолчанию). Для дисков ВМ
и баз данных остаётся `STORAGE_CLASS=local-path`. Обновляйте backend, worker
и frontend, не меняя глобальный `STORAGE_CLASS` ради сетевых дисков.

Перед созданием сетевого диска проверяется, что его StorageClass использует
OpenEBS LVM и `volgroup: vg-aegis`. Если класса или места нет, создание
отклоняется с объяснением — запасного перехода на local-path нет. Резерв
LVM учитывает реальные PVC и ожидающие PVC DataVolume без двойного счёта.

Проверка на сервере после обновления (без изменения данных):

```bash
kubectl get storageclass openebs-lvm -o yaml
kubectl get pvc -A -o wide
vgs --units g -o vg_name,vg_size,vg_free
lvs --units g -o vg_name,lv_name,lv_size,data_percent
```

Если StorageClass отсутствует, отдельно установите драйвер командой
`bash scripts/install-openebs-lvm.sh`. Затем создайте новый сетевой диск
на 1–2 ГБ в панели и подключите его к тестовой ВМ. У нового PVC должен быть
класс `openebs-lvm` и режим `Block`; прежние PVC сохраняют `local-path`.
Не удаляйте старый сетевой диск ради смены класса: сначала нужна отдельная
проверенная процедура переноса его данных.

## Обновление с прежней версии

Блоки настройки и отображения лимитов IOPS/МБ/с удалены. Текущие измерения
дисковой активности в мониторинге остаются — это метрики, не ограничения.
API больше не принимает настройки лимитов; лишние поля старого фронтенда
игнорируются и не включают ограничения снова.

Worker больше не применяет сохранённые лимиты. Для ВМ с прежними ненулевыми
значениями он снимает runtime-ограничения (`max`), затем обнуляет их в БД.
После успешной очистки cgroup этой ВМ больше не изменяется. Если ВМ выключена
или очистка не удалась, операция повторяется позже; ошибка пишется в журнал.
Старые поля БД сохранены для совместимости, диски и данные не удаляются.

```bash
cd /root/Hosting
docker compose logs --since 10m --tail 200 worker
```
