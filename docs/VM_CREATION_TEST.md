# Проверка всех полей создания ВМ

Поля формы и пользовательский #cloud-config теперь объединяются. Валидация
формата и совместимости выполняется до записи задачи в БД и очереди.

## Правила

- Пакеты из формы ставятся после ожидания сети, до пользовательского runcmd.
  `packages:` из YAML тоже сохраняется и обрабатывается стандартным модулем
  cloud-init. Наличие пакета в репозитории выбранной ОС заранее не гарантируется.
- SSH-ключ из формы сохраняется вместе с пользовательскими ключами. При наличии
  ключа парольная и keyboard-interactive аутентификация отключаются.
  Конфликт ssh_pwauth: true отклоняется до создания ВМ.
- Пользователи объединяются по name, файлы — по path. Для одинакового файла
  пользовательские значения имеют приоритет. Остальные списки объединяются без
  одинаковых элементов; runcmd/bootcmd сохраняют порядок и повторы.
- Пользовательский runcmd идёт после базового; неверная команда или неудачная
  установка пакетов возвращает ошибку cloud-init, а не успешный статус.
  Сама ВМ при этом не удаляется: ошибки смотрите в её консоли.
- Пользовательские scalar-настройки имеют приоритет, кроме конфликта SSH выше.
  При явном изменении пароля/пользователей учётные данные из панели могут перестать
  подходить; не меняйте их в объединённом тесте.
- PVC подключается отдельным диском без форматирования; NFS монтируется в
  /mnt/network_drive_0, _1 и далее по индексу элемента. Для NFS проверяется формат,
  но не доступность удалённой шары. Для PVC — наличие, права и отсутствие другой ВМ.
  В разделе «Сетевые диски» такой PVC отображается как «Подключён» с именем ВМ
  и подписью «Подключён при создании ВМ», включая уже созданные машины.
  До появления конфигурации ВМ диск показывается как «Подключается» и не доступен
  для повторного подключения/удаления. Статус не означает форматирование или
  монтирование файловой системы внутри гостя.
  Диски, добавленные при создании без hotplug, нельзя отключить кнопкой горячего
  отключения или удалить из этого списка, пока они используются. Их связь читается
  из Kubernetes без изменения БД и без включения каскадного удаления диска с ВМ.
- Поддерживается YAML #cloud-config по локальной официальной схеме cloud-init 26.1.
  MIME, shell-скрипты вместо YAML, aliases, duplicate keys и переопределение списков
  cloud-init-модулей в этом поле отклоняются с объяснением.
- Русский текст допустим в комментариях ключа/YAML, содержимом файлов и командах.
  Имена ВМ/PVC, пакетов и ключей YAML — латиницей. Русское имя исполняемой команды
  допустимо синтаксически, но без такого бинарника в госте будет command not found.

## Обновление на hosting

```bash
cd /root/Hosting
git pull
docker compose up -d --build backend worker frontend
```

Это не меняет уже созданные ВМ: cloud-init применяется при первом запуске новой ВМ.

## Один успешный тест на одной новой ВМ

На сервере **hosting** создайте ключ в новом каталоге (старые ключи не меняются):

```bash
task_key_dir=$(mktemp -d /root/hosting-ssh-test.XXXXXX)
ssh-keygen -t ed25519 -f "$task_key_dir/id_ed25519" -N '' -C hosting-test
cat "$task_key_dir/id_ed25519.pub"
printf 'Приватный ключ: %s\n' "$task_key_dir/id_ed25519"
kubectl get pvc -n default -o wide
```

Сохраните путь; приватный ключ не отправляйте. Через «Сетевые диски» создайте
**новый свободный** диск 1 ГБ, если свободного нет. Не используйте PVC, уже
подключённый к test/cloudinit-test или другой ВМ. Скопируйте точное имя нового PVC.

Создайте **Ubuntu 24.04**, имя **all-fields-test**, CPU **2**, RAM **2 ГБ**,
системный диск **20 ГБ**. Пакеты: `htop, curl, jq`. Сетевые диски: имя свободного
PVC. SSH-ключ: вся строка `.pub`. Кастомный cloud-init:

```yaml
#cloud-config
timezone: Asia/Yekaterinburg
write_files:
  - path: /var/tmp/hosting-userdata-test.txt
    permissions: '0644'
    content: |
      Привет! Кастомный Cloud-Init работает.
runcmd:
  - [sh, -c, 'printf "RUNCMD_OK\n" > /var/tmp/hosting-runcmd-test.txt']
```

После запуска подключитесь в той же сессии сервера. IP замените адресом **новой**
ВМ из панели. При первом подключении сверяйте отпечаток: из VNC внутри гостя
его показывает `sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`.

```bash
ssh -i "$task_key_dir/id_ed25519" -o IdentitiesOnly=yes \
  -o PreferredAuthentications=publickey ubuntu@IP_НОВОЙ_ВМ
```

**Внутри ВМ**, а не на hosting:

```bash
hostname
cat /etc/os-release
sudo cloud-init status --wait --long
dpkg-query -W -f='${Package}: ${Status}\n' htop curl jq
cat /var/tmp/hosting-userdata-test.txt
cat /var/tmp/hosting-runcmd-test.txt
timedatectl show -p Timezone --value
nproc
free -h
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
sudo /usr/sbin/sshd -T | grep -E '^(pubkeyauthentication|passwordauthentication|kbdinteractiveauthentication) '
```

Ожидается: all-fields-test, Ubuntu 24.04, cloud-init done без ошибок, три
установленных пакета, русский текст, RUNCMD_OK, Asia/Yekaterinburg, 2 CPU,
RAM около 2 ГБ (часть занята ядром), vda 20 ГБ и отдельный диск 1 ГБ.
Парольная/keyboard-interactive аутентификация выключена, публичные ключи включены.

Выйдите `exit` и **на hosting** проверьте, что без ключа SSH отказывает:

```bash
ssh -o PubkeyAuthentication=no \
  -o PreferredAuthentications=password,keyboard-interactive \
  -o NumberOfPasswordPrompts=1 ubuntu@IP_НОВОЙ_ВМ
```

Ожидается Permission denied. Если что-то не сработало, лог смотрите **в госте**:
`sudo tail -n 100 /var/log/cloud-init-output.log`. Скройте пароли/токены.
Никакие диски при этой проверке форматировать не нужно.

## Терминал панели при входе по ключу

Для ВМ со своим SSH-ключом вкладка «Терминал / SSH» показывает инструкцию
вместо парольного веб-терминала. Панель также не выполняет фоновый парольный
SSH-мониторинг такой ВМ. Это работает и для уже созданных ВМ после обновления;
переустановка гостя не нужна. Явный `ssh_pwauth: false` в YAML включает тот же режим.

Укажите в инструкции путь к вашему приватному ключу (без `.pub`). Это только
путь для команды: файл не загружается в панель. Для текущего теста на hosting
укажите путь, напечатанный при генерации ключа выше. Для доступа со своего
компьютера соответствующий ключ должен быть на этом компьютере.

Команда «С сервера hosting» использует внутренний IP ВМ. Команда «Со своего
компьютера» использует адрес hosting и внешний TCP-порт, проброшенный на 22.
Адрес сервера можно изменить: домен HTTP-панели за CDN может не принимать SSH.
Проверьте firewall и роутер; наличие команды не подтверждает доступность порта
из Интернета. Кнопки ведут в VNC и настройки портов. Для парольных ВМ сохраняется
веб-терминал, инструкция доступна под ним. Для Windows и TrueNAS SSH-вкладка
и эта инструкция не показываются.

## Ошибочный ввод — без создания дополнительных ВМ

Перед успешным созданием можно менять по одному полю и нажимать «Создать»:

| Поле | Неверный пример | Ожидаемый результат |
| --- | --- | --- |
| Имя | сервер, test vm, -test | Ошибка; имя не заменяется дефисами |
| Пакеты | нгинкс, curl,,jq, curl;echo test | Ошибка формата |
| PVC | диск | Ошибка формата |
| PVC | vol-1-does-not-exist | Ошибка отсутствующего/недоступного диска |
| PVC | имя уже занятого диска | Отказ подключения второй ВМ |
| NFS | 192.168.1.10, 999.999.1.1:/share | Требуется корректный адрес и путь |
| SSH | ключ, ssh-ed25519 AAAA, приватный ключ | Ошибка публичного ключа |
| Cloud-Init | runcmd: показать-систему | Ошибка структуры: нужен список |
| Cloud-Init | пакеты: [curl] | Неизвестное название YAML-ключа |
| Cloud-Init | незакрытая [, повтор timezone | Ошибка YAML |
| SSH + YAML | настоящий ключ + ssh_pwauth: true | Ошибка несовместимости |

Для YAML-примеров оставляйте первую строку #cloud-config. Эти попытки должны
отказаться **до создания** задачи. API возвращает список независимых ошибок
полей за один ответ 422; форма с неверным именем останавливается сразу.

Несуществующий пакет с правильным именем (например definitely-missing-test-package)
и команда `[показать-систему]` — **runtime**-ошибки, а не ошибки YAML. Их нельзя
надёжно определить до загрузки ОС. Автотесты проверяют неуспешный код выхода и
отсутствие ложного успеха. Не перезапускайте cloud-init рабочей ВМ ради этих тестов.
