# Бэкапы и снимки в личном S3

Новые ручные и плановые бэкапы Linux-ВМ, дисковые снимки и SQL-дампы
хранятся в отдельном приватном бакете владельца `aegis-backups-u<ID>`.
Администратор, запускающий копирование чужой ВМ, использует бакет её
владельца, не свой. Бакет создаётся при первом копировании и виден в
«S3 Хранилище», не расходуя лимит трёх обычных бакетов.

Ключи пользователя разрешают только чтение этого бакета. Загрузка файлов,
удаление объектов и удаление служебного бакета через S3-панель запрещены.
Копии удаляются через вкладки ВМ/БД; администратор MinIO всё ещё имеет
корневой доступ. В Windows-ВМ вкладки бэкапов и снимков скрыты, новые
копии и расписания для Windows запрещены.

## Обновление существующего сервера

```bash
cd /root/Hosting
git pull
sudo bash scripts/enable-vm-export.sh
docker compose up -d --build backend worker frontend
```

Скрипт включает `VMExport` без удаления существующих feature gates.
На новой установке gate уже включён в `install.sh`. Пользовательские
таблицы и колонка назначения бакета создаются/мигрируют при старте backend.
worker ждёт готовности схемы. Нужны доступные MinIO, CDI и KubeVirt Export
API; кластерные поды должны иметь доступ к MinIO по IP хоста и порту 9000.

## Что именно сохраняется

Снимок — полная дисковая точка восстановления, а не CSI/LVM-снимок и не
сохранение оперативной памяти. Она работает и с `local-path`.
Сохраняются все постоянные диски (включая подключённые дополнительные
диски), описание ВМ и параметры PVC. ISO/CD-ROM, containerDisk, cloud-init
и содержимое внешних Secret/ConfigMap отдельно не экспортируются.

ВМ выключается до экспорта и остаётся выключенной до конца выгрузки;
после завершения/обработки ошибки возвращается исходное состояние питания.
На файловой системе MinIO проверяется место под полный размер дисков плюс
5 ГБ резерва хосту. Полные raw-образы могут занимать существенно больше,
чем реально записанные данные гостя. Прогресс приблизительный, по дискам.

Структура бакета:

```text
vms/<VM ID>/backup/<archive ID>/disk-0.img, manifest.json
vms/<VM ID>/snapshot/<archive ID>/disk-0.img, manifest.json
databases/<DB ID>/backup_<name>_<timestamp>.sql
```

Восстановление сначала импортирует ВСЕ диски в новые CDI DataVolume.
Только после готовности всех импортов ссылки дисков переключаются одним
JSON Patch с проверкой версии и блокировки. CPU, RAM и сеть сохраняют
текущие настройки; конфигурация в manifest нужна для ручного восстановления.
При изменившемся составе дисков автоматическое восстановление отказывается
от переключения. Исходные диски не удаляются автоматически: это страховка
от потери данных. Они перечислены в `vm_archives.restore_data.originals`;
оператор может удалить их только после проверки восстановления и отсутствия
других ссылок. Вместимость учитывает staging и дополнительные импортные DV.

Очередь и стадии хранятся в PostgreSQL. После рестарта worker выгрузка
повторяется в тот же архив, а импорт/завершение продолжаются. Незавершённый
архив не показывается готовым. Пока операция активна, запуск/изменение
дисков и удаление ВМ заблокированы. Retention удаляет только готовые старые
S3-бэкапы той же ВМ и владельца.

## Старые копии и ограничения

Существующие локальные бэкапы и CSI-снимки остаются доступны в прежнем
месте; автоматического переноса в S3 нет. Для старых SQL-дампов остаётся
чтение из `database-backups`, с проверкой времени создания текущей БД,
чтобы не открыть копии предыдущей БД с переиспользованным именем.

MinIO по умолчанию хранится на том же сервере. S3 в этом случае защищает
от удаления/изменения диска ВМ, но не от потери физического сервера.
Для аварийного восстановления нужны отдельная копия S3, PostgreSQL панели
(метаданные очереди и архивов), `.env`/ключ шифрования и конфигурация кластера.
Не размещайте публично порт 9000 по HTTP; для удалённого чтения используйте
защищённый туннель или TLS-прокси. Presigned-ссылки для CDI действуют до 7 дней.

См. [KubeVirt Export API](https://kubevirt.io/user-guide/storage/export_api/).
После обновления сначала проверьте создание и восстановление копии на
тестовой Linux-ВМ: автоматические тесты не заменяют проверку вашего кластера.
