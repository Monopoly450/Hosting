# Руководство по обновлению сервера хостинга в университете

В этом документе описаны изменения, внесённые за сегодня, и приведена подробная инструкция по обновлению вашего основного сервера в университете.

---

## Что было сделано сегодня (и доработки):

1. **Исправлен перенос текста на телефонах**:
   * Текст под шкалами ресурсов (CPU, RAM, Диск) больше не накладывается друг на друга на узких экранах.

2. **Реальные лимиты ресурсов**:
   * Показатель «Доступно для новых ВМ» рассчитывается по физическим параметрам хоста.

3. **Управление пулом LVM из веб-интерфейса**:
   * Внедрена кнопка-шестерёнка и Slide-over панель для управления размером хранилища LVM (vg-aegis).

4. **Проброс LVM и утилит в Docker**:
   * В docker-compose.yml проброшены пути /var/lib/aegis и /run/lvm, а в бэкенд установлен пакет lvm2.

5. **Исправлена служба автозапуска LVM (aegis-lvm-loop.service)**:
   * Удалены жесткие префиксы /sbin/losetup и /sbin/udevadm. Теперь служба использует стандартный поиск путей в PATH из-под оболочки bash, что решает ошибку падения при старте.

6. **Поддержка Windows Server и RDP-портов**:
   * Добавлен шаблон создания ВМ с Windows Server.
   * Реализован автоматический проброс портов RDP (3389) с внешнего порта 33000 + последний октет IP на IP виртуалки.

7. **Оптимизация дискового ввода-вывода (IOPS) для жестких дисков (HDD)**:
   * Внедрен режим кэширования дисков writeback для Linux и Windows машин.

8. **Исправлена авторизация VNC консоли для пользователей**:
   * Код проверки токена VNC (vnc.py) теперь корректно декодирует JWT-токены пользователей. Администраторам разрешен доступ ко всем консолям, а обычным пользователям — строго к консолям их собственных ВМ.

9. **Проброс сетевых портов в KubeVirt (SSH/RDP)**:
   * В шаблоны создания ВМ добавлена секция ports для интерфейса masquerade. Это открывает входящий трафик на порты 22, 80, 443 (и 3389 для Windows).

10. **Проверка свободного места в LVM при создании дисков**:
    * Бэкенд запрашивает свободное место в `vg-aegis` и запрещает создание диска больше доступного лимита (с выдачей ошибки 400).

11. **Вывод пула LVM на дашборд**:
    * На главной странице добавлен блок «LVM Хранилище (PaaS)» с выводом общей емкости, занятого объема и свободного остатка в реальном времени.

12. **Русские статусы и защита от удаления**:
    * Все статусы ВМ переведены на русский язык («Запущена», «Остановлена», «Выключение...», «Запуск...», «Планирование...», «Импорт»).
    * Кнопка удаления ВМ заблокирована, пока машина полностью не выключится.
    * Запрещено подключать/отключать/удалять диски на выключенных или выключающихся ВМ для предотвращения конфликтов.

## Инструкция по обновлению сервера в университете:

Выполните эти шаги по очереди в терминале вашего сервера в университете:

### Шаг 1. Перейдите в рабочую папку и загрузите обновления из GitHub
```bash
cd ~/Hosting
git pull
```

### Шаг 2. Включите горячую замену дисков в KubeVirt (выполняется один раз на сервере)
```bash
kubectl patch kubevirt kubevirt -n kubevirt --type merge -p '{"spec":{"configuration":{"developerConfiguration":{"featureGates":["LiveMigration","SRIOV","NUMA","GPUDevice","HotplugVolumes","DeclarativeHotplugVolumes"]}}}}'
```

### Шаг 3. Примените обновлённую службу автозапуска LVM
Запустите скрипт установки хранилища LVM, чтобы обновить конфигурацию службы автозапуска:
```bash
sudo bash ./scripts/install-openebs-lvm.sh
```
> [!NOTE]
> Если при создании диска в будущем вы увидите статус Pending, а в выводе `kubectl describe pvc` будет ошибка `exit status 5`, это означает, что в системе зависли дубликаты loop-устройств. Очистите их следующими командами:
> ```bash
> sudo vgchange -an vg-aegis
> sudo losetup -D
> sudo systemctl restart aegis-lvm-loop.service
> ```

### Шаг 4. Пересоберите и запустите контейнеры Docker
```bash
docker compose up -d --build
```

## Проверка успешности установки:

1. **Проверьте статус контейнеров**:
   Убедитесь, что все службы запущены успешно (Up или healthy):
   ```bash
   docker compose ps
   ```

2. **Проверьте доступность LVM из контейнера бэкенда**:
   Зайдите в контейнер бэкенда и проверьте, видит ли он дисковый пул LVM:
   ```bash
   docker compose exec backend pvdisplay
   ```
   *(Команда должна вывести информацию о физическом томе /dev/loop0 или аналогичном)*.

3. **Проверьте интерфейс**:
   Откройте веб-панель администратора в браузере, перейдите к дискам, нажмите на шестерёнку настроек LVM справа и проверьте работу боковой панели.

## Развертывание Windows Server и настройка RDP:

В платформу Aegis добавлена возможность автоматического развертывания **Windows Server 2022**.

### 1. Создание и установка ВМ:
1. При создании виртуальной машины выберите **Windows Server** в качестве ОС.
2. После запуска откройте консоль **VNC** в панели Aegis.
3. Пройдите шаги установщика Windows. Когда программа спросит, куда устанавливать ОС, диск будет пуст. Нажмите **«Load Driver» -> «Browse»** (Загрузить драйвер -> Обзор).
4. Зайдите на CD-диск `virtio-win-...` (обычно диск `E:`), прокрутите вниз, найдите папку **`viostor`** -> папка **`2k22`** -> папка **`amd64`**. Нажмите **OK** и продолжите установку.

### 2. Установка драйверов и агента (внутри запущенной Windows):
1. Зайдите на рабочий стол Windows под пользователем `Administrator`.
2. Откройте проводник, перейдите на CD-диск `E:` (`virtio-win-...`) и запустите общий установщик:
   * **`virtio-win-gt-x64.msi`** (или `virtio-win_amd64.msi`).
3. Пройдите установку (кнопки Next -> Install). Это автоматически поднимет сеть (сетевая карта `NetKVM`), установит видеодрайвер для плавной графики и настроит Guest Agent для графиков в панели.

### 3. Включение удаленного доступа (RDP) и подключение:
1. В Windows откройте Поиск -> введите **«Remote Desktop settings»** -> включите переключатель **Enable Remote Desktop** в положение **On**.
2. В веб-панели Aegis в деталях вашей ВМ скопируйте строку подключения. Система сама рассчитает и пробросит внешний RDP-порт по формуле `33000 + последний октет IP ВМ`.
3. На вашем Mac откройте **Royal TSX**, установите бесплатный плагин **Remote Desktop (FreeRDP)** через Preferences -> Plugins, создайте подключение, указав IP сервера, проброшенный порт, логин `Administrator` и сгенерированный пароль. Подключение будет летать без тормозов!

## Дополнительная оптимизация хоста для HDD (BFQ и лимиты кэша):

Чтобы механический жесткий диск на хост-сервере работал максимально отзывчиво и **не вызывал полных зависаний ядра Linux** во время импорта тяжелых ВМ (например, Windows Server 2022 на 100 ГБ), необходимо ограничить размер грязного дискового кэша в оперативной памяти и переключить планировщик.

### 1. Настройка sysctl для предотвращения I/O Lockup (зависаний)
Мы заставим ядро Linux сбрасывать данные на диск гораздо раньше и мелкими порциями, исключая эффект "захлебывания" HDD:
```bash
# Применить настройки временно (до перезагрузки):
sudo sysctl -w vm.dirty_background_ratio=5
sudo sysctl -w vm.dirty_ratio=10

# Сохранить навсегда:
echo "vm.dirty_background_ratio=5" | sudo tee -a /etc/sysctl.d/99-aegis-hdd-tuning.conf
echo "vm.dirty_ratio=10" | sudo tee -a /etc/sysctl.d/99-aegis-hdd-tuning.conf
sudo sysctl --system
```

### 2. Включение Direct I/O для виртуального хранилища LVM
В файле `scripts/install-openebs-lvm.sh` мы добавили параметр `--direct-io=on` в службу монтирования loop-устройства. Это позволяет обходить двойное кэширование на хосте, снижая нагрузку на CPU и исключая сбои по памяти.
При повторном запуске скрипта службы:
```bash
sudo bash ./scripts/install-openebs-lvm.sh
```
служба пересоздастся с поддержкой Direct I/O.

### 3. Переключение планировщика диска на BFQ
Выполните на хост-сервере (где `sda` — имя вашего физического жесткого диска):
```bash
sudo sh -c 'echo bfq > /sys/block/sda/queue/scheduler'
```
*(Это предотвратит "подвисание" хоста во время активной записи данных виртуальными машинами).*
